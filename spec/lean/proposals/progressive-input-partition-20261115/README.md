# Persistent owner-local input partitions

Constructive proof package for the
[proposal](../../../../docs/design/bidirectional-progressive-input-partition-20261115.md).
See the [report](../../../../docs/reports/bidirectional-progressive-input-partition-20261115.md)
for complete nested annotations, acceptance results and limitations.

This replaces the withdrawn pure-forwarder solution. Separate method/block
owners remain. The declared scope is positive, unary prefix transfers with
empty real exclusions in the new executable examples. Initials are conditional
FLOW queries; actual offers carry the full T and their own layers. Older
mark/H/mx, cleaner and wrapper-repair packages are rechecked as dependencies.
No integrated native correspondence or universal termination is claimed.

Every cold certificate checks its whole state, not one selected row:
submitted domains, all current publications, original caller reply packets,
pending split, next rows and retained NORMAL records. It also checks another
round is a fixed point, successive same-direction trees, and actual backward
producer permission. Final assertions check both DATA and Target demand,
with the expected report identity. The reference Target adapter uses the
already selected ZERO/Target kernel.

The pure reference represents field paths as lists. The proposed storage
uses parent/accessor trie nodes and keeps at most one pending edge across an
owner's input frames for each direction. No discarded suffix is propagated
through calls. Input local-cell depth is a declared semantic change; output
C5 keeps the external row's original Dp and its FL+1 cap.
