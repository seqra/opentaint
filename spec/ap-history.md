# Access paths and storages — design history

This document records the design decisions of the AP spec and the reasons for them: the versions, the decisions of
the design reviews, the decision log, and the resolved questions of the interpreter. It is not normative.
[`ap.md`](ap.md) is the normative document for the AP, and [`interpreter.md`](interpreter.md) for the IR
interpretation. The tags F*n*, UD*n* and the resolved Q*n* occur only here.

Language: ASD-STE100 Simplified Technical English.

Current checkpoint: F72/F74/F75 rules, local demand and reduction certificates,
candidate-index equivalence, and base exactness are described in
[proof-status.md](proof-status.md). The proposals now use the checked current
demand reference. Status notes in older rows record their review date; the current
matrix is the source for remaining mode, W6/X, and pipeline/iteration obligations.

---

## 1. Versions

* Version 2 came from the first design review.
* Version 3 added the runs that strictly follow the demand. It used location-only rules for the strict demand. Two
  agreed rows then lose a real flow (programs 1 and 2, `RCases.p1_lost_U`, `p2_lost_U`).
* Version 4 made the emission mark-aware. The restricted runs became concrete, and neither row can fire
  (`RCases.p1_found_M`, `p2_found_M`). The model keeps the version-3 rules for comparison.
* Version 5 splits the spec in two (`ap.md`, `interpreter.md`). It removes the Universe exclusion (it never occurs
  with the edges of the interpreter), puts every `[any]` conclusion in the demand layer, separates micro edges from
  summary edges, and adds the mark exclusion, the cleaner, the type filter and the ND edges.

## 2. Decisions of the design reviews

| Topic | Decision |
|---|---|
| Layer | A propagation edge is in the normal or the demand layer (`~`, `Zero~`). Only the AP operations move it to the demand layer; the expected over-approximations of a path-insensitive engine do not. A micro edge has no layer. An `[any]` conclusion is ALWAYS in the demand layer. So "complete" means "normal layer" (ap.md now says "normal edge"). Since F69 the fourth tail `[any-taint]` (the result of an `[any]`-target source; forward only, with its own exclusion) is a normal-layer tail: a normal edge with it is complete. |
| Exclusion | ONE exclusion per path edge, shared by premise and conclusion. An exclusion is a finite set of accessors; "Universe" does not exist in the AP. Two merge rules; no union across different conclusions. |
| Mark | A premise has the mark `*` or `T`. A conclusion has `*`, `T`, or `*∖X` (the premise mark passes unless it is in `X`; a cleaner makes it). Since F71 a demand pattern with the mark `*∖X` (the entry pattern of a backward run that a run-1 summary conclusion gives) admits every concrete mark that is not in `X`, in the emission and in the restriction. Before F71 it counted as `*`. Since F72 no demand pattern has the mark `*∖X`: the hand-off replaces it by `*` (a larger demand), so a pattern has the mark `*` or `T`, and the `*∖X` pattern cells of F71 are dead. A summary keeps `*∖X`: it blocks a mark that cannot pass. A demand for a mark in `X` comes as its own concrete demand edge. Since F72 a restricted run can also have `*`-mark premises (FLOW premises) and `*` conclusions. |
| Read | A field read never changes an exclusion. Only a field write does. |
| Statics | One `ClassStatic` base with the class accessor. |
| Operations | One computation (delta-concat) and two operations on it: a MICRO EDGE applies to every overlapping fact; a SUMMARY EDGE applies only to a fact that satisfies its premise. |
| Ownership | The CALLER owns the subscriptions and applies the summaries. The CALLEE owns the added facts, the demand, the emission and its summaries; it restricts each summary by its demand before it publishes it. |
| Runs | Run 1 is unrestricted: it emits the most abstract facts. Every later run STRICTLY follows the demand of the previous run: the emission and the summary restriction. Before F72 the emission was `a ∩ D-c` with the mark of `a` for every pattern, and a restricted run was concrete. Since F70 the summary restriction is an INTERSECTION (the premise inside `D-c`, the tails met at `D-p`; since F71 also in the marks: the marks of the premise lie in the marks of `D-c`, and the conclusion mark meets the mark of `D-p`), and the hand-off gives the next run only the DEMAND EDGES: the published summary pieces that are not crossable. A crossable complete edge is a record. So the next forward run analyses only from the zero fact a method key that gets no demand edge and has no seed in its call subtree, for example a method key whose summary leaves are all crossable (F70 (D7)), and the demand patterns with an exit pattern only become smaller, as locations and, since F71, as marks (F70 (D8), F71 (5); the zero demand and the seed paths are not part of this claim). Since F72 a restricted run is NOT concrete. In both directions a `*` pattern (a demand pattern with the mark `*`) emits its FLOW FORM `(base, path, flowK tail, *)`, one initial fact for every added fact under the pattern (SHARING); a concrete pattern emits `a ∩ D-c` with the mark of `a`, as before. The hand-off replaces the pattern mark `*∖X` by `*`, and the restricted runs have no request rules. The theorems of F70 and F71 about the restricted runs (the iteration, the exclusion, the narrowing) are for the concrete design. For F72 their Lean model is PENDING. |
| Requests | The task rule for the answer (no chain deeper than the request). Requests stand for the whole run. Requests exist ONLY in run 1. Before F72 a restricted run raised no request because it was concrete (F35). Since F72 the restricted closures have no request rules: on a `*` fact an operation that needs a concrete mark gives nothing (the mark gate of a micro edge with a concrete premise mark, the sink check, the part of a cleaner). The answers of run 1 make the concrete-mark summaries, and the hand-off gives them as concrete patterns (or as records if they are crossable). |
| Conjunction | A rule with several mark literals on different facts makes an ND edge: a SET of premises. |
| Cleaner | A cleaner splits a `*`-mark fact by the mark: the fact continues as `*∖{T}`, and the mark `T` is requested and cleaned exactly on the concrete answer. Since F72 this request occurs only in run 1: in a restricted run the `*` fact continues as `*∖{T}` with no request, and a flow of `T` comes from a concrete pattern. |
| Type filter | A prefix-closed predicate on paths; it only drops facts that have no real location. |
| Report | Every forward run reports every real vulnerability (with B). Confirmed vulnerabilities persist. A demand vulnerability that the next forward run does not report is refuted. Since F70 the backward run seeds only the DEMAND entries of the report (and, during the run, the sink alternatives whose end-fact action a requirement reaches: F70, the review round), so every forward run reports every real vulnerability that no earlier forward run confirmed (`HandoffMain.iteration_generalN`). Since F72 this is the claim R6 for the restricted runs with abstract marks. Its Lean model is PENDING; `HandoffMain.iteration_generalN` is for the concrete design. A sink fires only under a concrete premise, so the confirmation does not change. |

## 3. Notes removed from ap.md

These notes were inline in ap.md version 5. They explain a past state, not a current rule.

* Merge rules (ap.md §3.3). The current `EdgeNonUniverseExclusionMergingStorage` makes a union of exclusions across
  two edges. It was sound only with the old refinement.
* W6 (ap.md §2.3). It was decided for version 5 (F41) that the results of the any-field rules go to the demand layer:
  an `[any]` result never makes a record and never confirms.
* Satisfaction (ap.md §4.3). The version-4 form `RCore.satIold` compared the marks in both directions. It rejected a concrete
  fact against a `*`-premise record, which disabled record reuse. `RCore.satI_markSub` and `satI_conc_record` show that
  `satI` accepts these cases; `satIold_markSub_fails` and `satIold_conc_record_fails` show that the old form rejects
  them. The overlap test `satO` and its false demand vulnerability were a review argument, not modelled.
* Cleaner (ap.md §4.7). The `part` row of an all-marks cleaner on a `*`-mark fact normalises the result (F45): without
  it W2 failed (`Invariant` round 5).
* Type filter (ap.md §4.8). The two summary-side filters of today were dropped "in version 5".
* Restriction (ap.md §6.4, §7.4, §8.6). The table of §6.4 is the rule agreed with the user (`restrictU`). The
  version-3 repair `restrictS` keeps a `*` conclusion above `D-p`. In a concrete run both give the same run
  (`RExact.restrict_U_eq_S`), and the contract of `restrictS` holds (`RCore.restrictS_contract`). The demand store
  index also serves the version-3 form (`_S` lemmas). F70 replaced `restrictU` in §6.4 by the intersection
  `Handoff.restrictI`, which satisfies C5 directly for a premise inside `D-c` (`Handoff.restrictI_contract`). F71
  made `Handoff.restrictI` mark-aware: the premise lies inside `D-c` in its locations and its marks
  (`Handoff.insideB`), and the conclusion mark meets the mark of `D-p` (`Handoff.concMarkB`). C5 now reads `D-c` and
  `D-p` with their marks. `restrictU` and the F70 form read them as locations only, so they keep a conclusion with
  another mark (`Handoff.RVec.vMark_user_restrictU`, `vMark_user_loc`).
* Version-3 theorems (ap.md §10.7): `RCore.emitS_contract`, `emitU_fails`, `restrictU_fails`; `RCases.p1_lost_U`,
  `p2_lost_U`; `RMain.iteration_sound_S`. The location-only rules: the agreed rows lose programs 1 and 2.
* Test vectors (ap.md §13 item 1). "The F16 vectors" were the vectors of `lostCorr` that give an `[any]` result in the
  normal layer of the model.
* Support (ap.md §10.3). `Confirmed.rev2_not_confirmed` is the counter-example of a review.
* Universe (ap.md §11). Two notes compared the Lean `applyEdge` and the Kotlin reference form on a `$`-premise edge: on
  an `[any]` fact with a `*` target Lean gives `$` and Kotlin `[any]` in the demand layer; on a `*` fact at `r = []`
  Lean gives `*/Universe`, which `AFact.norm` maps to `$`. Both cases need an edge that S8 or I7 forbids. ap.md now
  makes `concat` assert S8 and I7, so the notes are not necessary.
* Exceptions (ap.md §11, interpreter.md G1). Out of scope for now (F51).
